# كوادرنا — عرض تجريبي لطلبات الإجازة

عرض تفاعلي (React) لمسار طلب إجازة واحد: **موظف ← مدير ← موارد بشرية ← موظف**، مع صفحة تعريفية (Landing) تقود إليه.

> **حدود هذا العرض.** هذا عرض توضيحي للمبيعات، وليس نظامًا جاهزًا للتشغيل.
> البيانات والحسابات افتراضية، وتسجيل الدخول اختيار دور وليس مصادقة، وكل الحالة تُحفظ في تبويب المتصفح فقط.
> لا يوجد خادم ولا قاعدة بيانات ولا تكاملات خارجية. لا يمثل هذا العرض امتثالًا لأي نظام تنظيمي.

## ما الذي يعمل فيه

| الدور | ما يمكن تجربته |
|---|---|
| الموظف | تقديم طلب إجازة (الإقرار بتنبيه الرصيد عند اللزوم)، ثم متابعة القرار وسبب الرفض إن وُجد |
| المدير | قائمة الطلبات (جدول على الشاشات الكبيرة، بطاقات على الجوال)، البحث والتصفية بالحالة والمخاطر والاستحقاق، تفاصيل الطلب والموافقة، الرفض بسبب من خمس فئات |
| الموارد البشرية | القرار النهائي على الطلبات المحوَّلة (رصيد منخفض) بنص حر من ١ إلى ٥٠٠ حرف |

## التشغيل

```bash
npm install
npm run dev
```

يفتح العرض على `http://localhost:5173`. الصفحة التعريفية على `/` والعرض التفاعلي على `/demo`.

### الحسابات الافتراضية

كلها وهمية وتظهر في شاشة الدخول نفسها: `employee-demo`، `manager-demo`، `hr-demo`، وكلمة المرور `Demo2026!`.
«إعادة ضبط التجربة» ترجع الطلبات إلى حالتها الأولى وتسجّل الخروج.

## الأوامر

```bash
npm run build      # فحص الأنواع ثم بناء الإنتاج في dist/
npm run lint       # oxlint
npx vitest run --maxWorkers=1   # اختبارات الوحدة والمكوّنات
npx playwright test             # اختبارات المتصفح (تشغّل خادمها الخاص على المنفذ 5173)
```

اختبارات المتصفح تستخدم Chrome المثبّت على الجهاز، وتحتاج إلى عدة دقائق.

## البنية

```text
src/domain/leave/    قواعد الطلب والانتقالات والمحدّدات والبيانات التجريبية (دوال نقية)
src/demo/            حالة العرض والحفظ والأدوار وواجهة الدخول والإطار
src/pages/           صفحات المدير والموارد البشرية والموظف
src/features/landing/ الصفحة التعريفية
tests/e2e/           اختبارات المتصفح
```

القرارات تمرّ دائمًا عبر `src/domain/leave/transitions.ts` وما يستند إليه، ولا تُتخذ داخل الواجهة.

## الاستضافة

العرض تطبيق صفحة واحدة: يجب أن يعيد الخادم `index.html` لأي مسار (مثل `/demo`).
رابط التواصل في الصفحة التعريفية يُضبط بالمتغيّر `VITE_BUYER_CONTACT_HREF` عند البناء.

## قيود معروفة

- الساعة ثابتة في العرض (18 يناير 2026، 10:00 بتوقيت الرياض).
- رصيد الموظف ثابت (٣ أيام) ولا ينقص بالطلبات المقدّمة.
- تصفية الاستحقاق تفرّق بين «متأخر» و«غير متأخر» فقط؛ لا توجد حدود معتمدة لـ«قريب الاستحقاق»، ولا ترتيب قابل للتغيير للقائمة.
- على عرض الجهاز اللوحي (نحو ٧٦٨–١٠٠٠ بكسل) يبقى الجدول مقروءًا وقابلًا للاستخدام لكنه أطول من المعتاد؛ وهذا قيد بصري بسيط مقبول.
- لا مسارات توضيح أو سحب أو إعادة تقديم أو معالجة.
- الواجهة عربية (RTL) بالنمط الفاتح فقط.
- جرى التحقق في Chrome على سطح المكتب؛ لم تُجرَ اختبارات على أجهزة حقيقية أو Safari أو Firefox أو قارئ شاشة.
